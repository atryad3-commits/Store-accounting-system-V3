# گزارش جامع بررسی معماری و کدهای پروژه

با بررسی دقیق کدهای پروژه، معماری فرانت‌اند و بک‌اند، و ساختار فایل‌ها، گزارش زیر شامل مشکلات، باگ‌ها، و راهکارهای بهبود پروژه تهیه شده است.

---

## ۱. معماری کلی و مشکلات ساختاری (Architecture & Structural Issues)

### الف) فایل `src/App.tsx` (Monolithic Component)
*   **مشکل:** این فایل با بیش از ۴۶۰۰ خط کد، تبدیل به یک گلوگاه (Bottleneck) شده است. مدیریت تمام ماژول‌ها (حسابداری، انبار، CRM و ...) و رندرینگ آن‌ها در یک فایل انجام می‌شود. این موضوع خوانایی کد را به شدت کاهش داده و توسعه تیمی را غیرممکن می‌کند.
*   **روش رفع:** استفاده از کتابخانه `react-router-dom` برای مسیردهی (Routing). هر ماژول باید تبدیل به یک صفحه (Page) مجزا شود (مثلاً `/accounting`، `/crm`) و با استفاده از `React.lazy` بارگذاری شود (Code Splitting).

### ب) مدیریت وضعیت (State Management)
*   **مشکل:** استفاده افراطی از هوک‌های محلی و `useAppController` و پاس دادن متوالی پراپ‌ها (Prop Drilling) به کامپوننت‌های فرزند. این کار باعث رندرهای مجدد (Re-renders) غیرضروری و افت شدید پرفورمنس می‌شود.
*   **روش رفع:** استفاده از ابزارهای مدیریت وضعیت مدرن مانند **Zustand** یا **Redux Toolkit** برای مدیریت یکپارچه وضعیت (State) اپلیکیشن.

### ج) سرویس‌های داده (Data Services)
*   **مشکل:** فایل `src/services/dataService.ts` با بیش از ۳۲۰۰ خط کد، مسئولیت تمام درخواست‌های API و مدیریت کش دستی را بر عهده دارد. این فایل به شدت در هم تنیده است.
*   **روش رفع:** شکستن این فایل به سرویس‌های دامنه-محور (Domain-driven) مانند `productService.ts`، `invoiceService.ts` و `authService.ts`. استفاده از **React Query (@tanstack/react-query)** به جای کش دستی برای مدیریت بهینه API ها.

## ۲. مشکلات بک‌اند و دیتابیس (Backend & Database Security)

### الف) آسیب‌پذیری امنیتی بحرانی (Critical Security Flaw)
*   **مشکل:** در فایل `server.ts`، روت‌های دریافت و ارسال داده (مانند `app.get('/api/data/:key')` و `app.post('/api/data/:key')`) فاقد هرگونه مکانیزم بررسی توکن و احراز هویت (JWT Verification) هستند. در حال حاضر، هر فردی با دانستن آدرس API می‌تواند تمام داده‌های سیستم (حتی اطلاعات کاربران و فاکتورها) را دریافت یا ویرایش کند.
*   **روش رفع:** ایجاد و اعمال یک Middleware برای بررسی `accessToken` روی تمامی روت‌های مربوط به `api/data` و `api/db`. تنها روت‌های لاگین باید عمومی باشند.

### ب) معماری پایگاه داده (Database Anti-Pattern)
*   **مشکل:** در فایل `server.ts`، چه در SQLite و چه در PostgreSQL، از یک جدول مشترک به نام `store` با ستون‌های `key` و `value` (به صورت رشته JSON) استفاده شده است. این یعنی دیتابیس به صورت Key-Value Store استفاده می‌شود که کاملاً اشتباه است. با این روش، امکان استفاده از قابلیت‌های مهم دیتابیس‌های رابطه‌ای (مثل Indexing، JOIN ها، Foreign Keys و جامعیت داده) از بین می‌رود و در صورت افزایش داده‌ها، سیستم به شدت کند می‌شود.
*   **روش رفع:** طراحی مجدد اسکیما (Schema) پایگاه داده و استفاده از یک ORM استاندارد (مانند **Prisma** یا **Drizzle ORM**). هر موجودیت (Entity) باید جدول اختصاصی خود را داشته باشد (مانند جداول `Users`، `Invoices`، `Products`).

## ۳. باگ‌های مشاهده و رفع شده (Bugs)

*   **باگ منوی تنظیمات:** باگ مربوط به قرار گرفتن منوی تنظیمات و مدیریت به زیر منوی اصلی (تداخل z-index) و درخواست برای استفاده از آیکون به جای متن، **در آخرین تغییرات رفع گردید**. مقادیر `z-index` هدر روی `70` و کانتینر منوی اصلی روی `60` تنظیم شد تا منوی کشویی به درستی روی سایر اجزا قرار گیرد.
*   **باگ‌های پرفورمنس:** به دلیل یکپارچگی بیش از حد در `App.tsx`، تعامل با برخی فرم‌ها باعث کندی و لگ در تایپ کردن یا انتخاب گزینه‌ها می‌شود (Re-render شدن تمام صفحه به جای یک کامپوننت).

---

## ۴. مواردی که برای بهتر شدن پروژه نیاز است (Improvements)

۱.  **بهینه‌سازی بیلد (Build Optimization):** در زمان بیلد Vite هشدار می‌دهد که حجم باندل‌ها بیش از ۵۰۰ کیلوبایت است (`chunk size warning`). این مشکل با Code-splitting (استفاده از Lazy Loading برای مسیرها) برطرف می‌شود.
۲.  **اعتبارسنجی داده‌ها (Data Validation):** در سمت سرور هیچ‌گونه اعتبارسنجی (Validation) روی داده‌های ورودی انجام نمی‌شود. استفاده از کتابخانه‌هایی مثل **Zod** یا **Yup** هم در فرانت‌اند و هم بک‌اند ضروری است.
۳.  **مدیریت لاگ‌ها و خطاها:** راه‌اندازی ابزارهایی مانند **Sentry** برای پایش خطاهای سمت کاربر و سرور تا در صورت بروز مشکل، گزارش دقیق ثبت شود.
۴.  **داکرایز کردن دیتابیس:** انتقال کامل به PostgreSQL و حذف SQLite محلی برای پایداری بیشتر.

---

## ۵. لیست کارهایی که باید انجام شود (Action Items)

به ترتیب اولویت (باید در اسرع وقت برنامه‌ریزی شوند):

1.  🔴 **فوری:** اعمال Middleware احراز هویت (Auth Middleware) در `server.ts` برای محافظت از داده‌های کاربران.
2.  🟠 **مهم:** ریفکتور `App.tsx` و پیاده‌سازی `react-router-dom` برای شکستن صفحه به مسیرهای مختلف.
3.  🟠 **مهم:** ریفکتور معماری دیتابیس (جایگزینی مدل Key-Value با جداول Relational نرمال‌سازی شده) با استفاده از Prisma/Drizzle.
4.  🟡 تفکیک `dataService.ts` به فایل‌های مجزا بر اساس هر موجودیت.
5.  🟡 نصب و پیاده‌سازی React Query برای حذف کش‌های دستی و مدیریت بهتر وضعیت سرور در فرانت‌اند.
6.  🟢 اضافه کردن Validation به API های سمت بک‌اند.
